# Virtual Ride Unity

結論：ルームバイクの漕ぐ速さに合わせて、Unityで生成した3Dの田園コースを走る実験用プロトタイプです。既存映像は使わず、道路、草地、湖、木々、村、山、自転車視点を起動時に生成します。

## 現在できること

- PCカメラでペダル周辺の周期運動を読み取り、回転数（rpm）と速度を推定
- 山並み・雲のある空・枝付きの木々・草花・波立つ湖面・桟橋・村を生成（景観版 `valley-2026.09`）
- 視点は「揺れなし・視野角固定」が初期設定。実験前に穏やかな揺れへ切替可能
- 「景色に集中」表示で計器とカメラプレビューを隠し、体験への没入を優先できる
- 参加者が漕ぐことに集中できる自動操舵の周回コース
- 速度、回転数、距離、走行時間、平均速度、最高速度を表示
- カメラがなくても、キーボードで速度を模擬して体験を確認
- カメラ、キーボードに加え、標準BLE CSC対応のケイデンスセンサーを接続可能
- カメラ映像はPC内だけで処理し、保存も送信もしない
- 匿名の参加者IDと実験条件を指定し、速度・回転数・距離などをCSVへ記録（試行時間の自動保存とイベントマーカー付き）

## 最初の起動

1. Unity Hubを開き、右上のアカウントからサインインします。
2. Unity Personal（無料）のライセンスを有効にします。
3. Unity Hubの「追加」または「Add project from disk」で、このフォルダを選びます。
4. Unity `6000.5.7f1` で開きます。
5. `Assets/Scenes/VirtualRide.unity` を開き、上部の再生ボタンを押します。

世界と自転車視点は起動時に自動生成されます。外部アセットの読み込み待ちはありません。

## Quest 3 単体版の操作とPC内蔵カメラ

Quest版では手をHUDへ向け、親指と人差し指をつまむとボタンを選べます。Touchコントローラーを使う場合はHUDへ向けてトリガーを押します。いずれもビルド後にQuest実機で位置と反応を確認してください。

PC内蔵カメラを使う場合は、PCで `Builds/Windows/VirtualRide.exe` を起動します。「カメラ計測」を選び、映像を確認してから実験設定の「Questへ送信: ON」を押してください。Quest版は「PC中継」を選びます。PCとQuestは同じWi-FiかiPhoneテザリングへ接続してください。接続しない場合はWindows版の「QuestのIP」欄にQuestのIPアドレスを入力します。`Builds/Quest/VirtualRide.apk` はQuestにインストールするAndroid用ファイルで、PCでは起動しません。Quest側の「Quest USB」はQuestへ直接接続したカメラ用で、PC内蔵カメラは表示されません。Quest USBカメラの認識は実機未検証です。中継するのは速度・回転数などの数値だけで、カメラ映像は送信しません。

## 操作

| 操作 | 内容 |
|---|---|
| `↑` / `W` | 手動速度を上げる |
| `↓` / `S` | 手動速度を下げる |
| `Space` | 停止／再開 |
| `C` | カメラ計測へ切り替える（記録中は不可） |
| `K` | キーボード計測へ切り替える（記録中は不可） |
| `F` | 全画面表示 |
| `H` | ヘルプ表示 |
| `R` | スタート地点・距離・時間などをリセット（記録中は不可） |
| `Tab` | 通常表示／景色に集中を切替（記録中は固定） |
| `F7` | 実験設定を開く |
| `Esc` | 設定画面を閉じる／使い方を開く |
| `F8` | 記録中: 指示イベントを打つ |
| `F9` | 記録中: 休息イベントを打つ |

画面下のボタンでも同じ操作ができます。設定・使い方が開いている間は文字キーや矢印による走行操作を無効にします。記録中の F8 / F9 は設定画面内でも使えます。

下部の「BLEセンサー」から周辺機器を検索し、標準CSC対応センサーを選んで接続できます。BK9Cの実機接続はセンサー到着後に確認してください。

## 実験データを記録する

1. 使う入力（キーボード、カメラ、Bluetoothセンサー）を先に選びます。カメラの場合は片足／両足と感度も開始前に合わせます。
2. 画面下の「実験記録」を押します。
3. 氏名ではなく `P001` のような匿名の参加者IDを入力します。
4. `baseline` など、実験計画で決めた条件名を入力します。
5. 必要なら試行時間を秒で入れます。空欄または `0` は手動終了です。
6. 視点・表示・走行音を選び、「記録を開始」を押します。保存先を開けた場合だけ同じスタート地点・距離0・表示速度0へ戻り、記録が始まります。入力方式・カメラ設定・表示・音は試行中固定です。
7. 記録中は「指示」「休息」、またはメモでタイムスタンプ付きイベントを残せます（F8 / F9 でも指示・休息）。
8. 制限時間に達するか、「記録を終了して保存」で走行を停止し、保存結果を表示します。「保存フォルダを開く」からデータを確認できます。

試行時間は一時停止中も進みます。Spaceによる停止／再開は `pause` / `resume` イベントとして記録します。開始の入力不備や二重押しでは走行値を消しません。保存エラーの場合は停止して警告を出し、途中までのファイルを残します（要約JSONが完成していない可能性があります）。

保存先は Windows ではドキュメント内の `VirtualRideResearchData` です。macOS / Linux でも Documents 配下が使えればそこへ保存し、使えない場合は Unity の `persistentDataPath/VirtualRideResearchData` へフォールバックします。実際の場所は実験記録画面に表示されます。カメラ映像は保存せず、入力から得た数値・走行状態・イベントだけを記録します。列の定義と分析上の注意は [Docs/RESEARCH_LOGGING.md](Docs/RESEARCH_LOGGING.md) を参照してください。

記録中に入力方式を切り替えようとすると、切り替わらずに理由が表示されます。カメラ計測中の回転数・速度は未検証の推定値であり、画面にもその旨を表示します。

## 映像の速度を比較する実験

実験設定（F7）の「映像」で、景色の進み方を2つの条件から選べます。

- **ペダル連動**：ペダルの推定速度に合わせて景色が進みます（従来どおり）。
- **一定速度**：ペダルを漕いでも止めても、設定した速度（5〜35 km/h、0.5刻み）で景色が進みます。ペダルの回転数・推定速度は通常どおり計測し、CSV の `cadence_rpm` と `input_speed_kph` に記録します。景色の速度は `display_speed_kph` に記録されます。

一定速度の値は「直前の平均 ○ km/h」ボタンで、直前の試行の平均速度に合わせられます。たとえばペダル連動の試行の直後に押すと、同じ参加者の平均速度で一定速度条件を行えます。

映像の速度以外の条件をそろえるため、両条件とも次を同じにしてください。

- 「ペダル映像: 表示／非表示」：非表示にすると、ペダル確認パネルのカメラ映像を隠します。計測は続きます。
- 「表示: 景色に集中」：速度計やペダル確認パネルを隠します。計器を表示したままだと、一定速度条件では画面の速度がペダルと合わないことに参加者が気づく可能性があります。
- 視点・走行音・試行時間

これらの設定は記録中は変更できません。開始時の値を要約JSONの `videoSpeedMode`、`fixedVideoSpeedKph`、`pedalPreviewVisible` に記録します。一定速度条件では、一時停止（Space）の間だけ景色が止まります。カメラが検出できない間も景色は進みます。

## カメラ計測の置き方

1. USBカメラ（または内蔵カメラ）に、ペダルと足元が横から映るようにします。USBカメラはアプリを起動する前に挿しておくと確実です。
2. カメラ自体は揺れないように固定します。
3. 画面の「カメラ計測」を押します。
4. 左の「ペダル確認」でカメラ名の横の ◀ ▶ を押し、ペダルが映るカメラを選びます。選んだカメラは次回の起動時も使われます。
5. 背景の人や物が動く場合は「計測範囲」を押し、緑の枠をペダル付近（全体／下半分／左半分／右半分／中央）に合わせます。
6. 3〜5秒ほど一定のペースで漕ぎます。
7. 「検出中」と回転数が表示されたら走行が始まります。

両足が映るか片足だけ映るか、感度、カメラ、計測範囲は、実験記録を始める前に合わせてください。記録中は変更できません。カメラの回転数・速度は未検証の推定値です。カメラ映像の差分だけをメモリ上で計算し、映像ファイルは作りません。

映像が真っ暗なまま2秒続くと「映像が真っ暗です」、映像が3秒届かないと「カメラ映像が止まっています」と赤く表示し、走行を止めます。カメラのシャッター、Windows のカメラ許可、別アプリ（Teams・Zoom など）の使用を確認し、「再接続」または ◀ ▶ で別のカメラを選んでください。

## 反応テスト（実験前の確認）

カメラの置き方ごとに、回転数の誤差と反応の遅れを測れます。「カメラ計測」で「映像: ペダル連動」にし、F6（または実験記録画面の「反応テスト」）を押します。

1. 準備5秒: 止まったまま待ちます。
2. 「漕いでください 50 rpm」: カチッという音1回ごとに片足を踏み込みます（1回転で2回）。12秒続きます。
3. 「止めてください」: 8秒止まります。
4. 65 rpm、80 rpm でも同じことをくり返します（合計約65秒）。

結果画面には、合図から回転数を検出するまで・景色が目標速度の半分に達するまで・停止と判定するまで・景色が止まるまでの秒数と、最後の6秒間の平均回転数と誤差、検出率が出ます。秒数には人が合図に反応する時間（約0.3〜0.5秒）が含まれます。結果は `ドキュメント\VirtualRideResearchData\response-tests` に JSON（要約）と CSV（フレームごとの値）で保存され、カメラ映像は保存しません。

目安として、回転数の誤差が±5%以内、検出率が90%以上、停止判定が約1.5秒以内であれば、その置き方で実験を始めてよいと考えられます（この基準は研究計画に合わせて決めてください）。参加者や日が変わってカメラを置き直したときにも1回行い、結果を実験記録と一緒に保管すると、データの質を後から説明できます。

反応テストは、音に合わせて漕ぐ人の正確さにも左右されます。より厳密に確かめる場合は、画面とペダルを同時にスマートフォンのスロー撮影で撮り、コマ数から遅れを数えるか、ケイデンスセンサーの値と比べてください。

### 推定方法（camera-cadence-2026.09b）

カメラの各フレームで、計測範囲内の明るさの変化量を求め、直近3.2秒分を毎秒30点にそろえてから、0.2秒ごとに自己相関で周期を求めます。最も短い強い周期を選び、山の位置を補間して回転数を細かく求めます。直近0.7秒の動きが小さければ、過去の動きにかかわらず停止と判定します。景色の速度は毎秒9 km/h で加速し、毎秒12 km/h で減速します。

合成した動き信号で確かめた結果（スモークテストで毎回確認）では、両足が映る場合は漕ぎ始めから約1.7秒で検出し、誤差は0.2%以内、止めてから約0.5〜0.8秒で停止と判定しました。片足だけが映る場合は検出に約2.8秒かかるため、両足が映る置き方をおすすめします。実際のカメラ映像での精度は、反応テストや基準センサーで確かめる必要があります。

## Windows版を作る

Unityメニューの `Tools > Virtual Ride > Build Windows` を選ぶと、`Builds/Windows/VirtualRide.exe` が作られます。BluetoothブリッジはStreamingAssetsからWindowsビルドへ同梱されます。`Builds` は自動生成物なのでGitの対象外です。

## 専用センサーへの拡張

走行部分は `IRideInputSource` だけを参照します。Windows版はBLE CSC標準サービス（`0x1816` / `0x2A5B`）を読む接続画面を備えています。BK9C実機が未到着のため実機接続と測定性能は未検証です。詳しくは [Docs/SENSOR_INTEGRATION.md](Docs/SENSOR_INTEGRATION.md) を参照してください。

## 現時点の注意

- カメラ方式は「動きの周期」からの推定です。照明、服装、背景、カメラ位置で精度が変わります。
- 現段階は体験と実験手順を検討するためのプロトタイプで、速度計測の妥当性検証はまだ行っていません。
- 「揺れなし」は演出上の揺れと視野角変化を抑える設定で、体調への影響が検証済みという意味ではありません。不快な場合は中断してください。
- 景観の配置・天候・ルートは再現可能な固定条件です。波のアニメーション位相やPCの描画間隔まで同一とは限りません。
- 記録機能はデータ収集の土台です。研究利用前に、カメラ推定値と基準センサー値の一致度を別途検証してください。
- Bluetooth入力は実装済みですが、BK9C実機との接続・反応時間・精度は未検証です。
- 初版は自動操舵です。ハンドル操作、分岐、障害物、ゲーム課題は後から追加できます。

## 主な構成

```text
Assets/VirtualRide/Scripts/
  Core/    走行全体の制御、自転車視点
  Input/   キーボード、カメラ、Bluetooth入力
  World/   周回経路と3D景観の自動生成
  UI/      速度や計測状態の画面表示
```

## 開発時の自動確認

Windowsビルドを `-virtualRideSmokeTest -smokeOutput <出力フォルダ>` 付きで起動すると、模擬走行・入力ロック・開始失敗・時間終了・書込み失敗・JSONの文字処理を確認し、景観5地点と設定画面のPNG、`result.json`、短時間の描画計測 `performance.json` を出力して終了します。カメラは起動しません。画像出力はこの明示的なQAモードだけの機能で、通常の実験記録では画面・カメラ画像を保存しません。
