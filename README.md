# Virtual Ride Unity

結論：ルームバイクの漕ぐ速さに合わせて、Unityで生成した3Dの田園コースを走る実験用プロトタイプです。既存映像は使わず、道路、草地、湖、木々、村、山、自転車視点を起動時に生成します。

## 現在できること

- PCカメラでペダル周辺の周期運動を読み取り、回転数（rpm）と速度を推定
- 山並み・雲のある空・枝付きの木々・草花・波立つ湖面・桟橋・村を生成（景観版 `valley-2026.09`）
- 視点は「揺れなし・視野角固定」が初期設定。実験前に穏やかな揺れへ切替可能
- 「景色に集中」表示で計器とカメラプレビューを隠し、体験への没入を優先できる
- 参加者が漕ぐことに集中できる自動操舵の周回コース
- 速度、回転数、距離、走行時間、平均速度、最高速度を表示
- カメラがなくても、キーボードで速度を模擬して体験を確認
- 入力部分を独立させ、将来のBluetoothなどの専用センサーへ交換可能
- カメラ映像はPC内だけで処理し、保存も送信もしない
- 匿名の参加者IDと実験条件を指定し、速度・回転数・距離などをCSVへ記録（試行時間の自動保存とイベントマーカー付き）

## 最初の起動

1. Unity Hubを開き、右上のアカウントからサインインします。
2. Unity Personal（無料）のライセンスを有効にします。
3. Unity Hubの「追加」または「Add project from disk」で、このフォルダを選びます。
4. Unity `6000.5.7f1` で開きます。
5. `Assets/Scenes/VirtualRide.unity` を開き、上部の再生ボタンを押します。

世界と自転車視点は起動時に自動生成されます。外部アセットの読み込み待ちはありません。

## 操作

| 操作 | 内容 |
|---|---|
| `↑` / `W` | 手動速度を上げる |
| `↓` / `S` | 手動速度を下げる |
| `Space` | 停止／再開 |
| `C` | カメラ計測へ切り替える（記録中は不可） |
| `K` | キーボード計測へ切り替える（記録中は不可） |
| `F` | 全画面表示 |
| `H` | ヘルプ表示 |
| `R` | スタート地点・距離・時間などをリセット（記録中は不可） |
| `Tab` | 通常表示／景色に集中を切替（記録中は固定） |
| `F7` | 実験設定を開く |
| `Esc` | 設定画面を閉じる／使い方を開く |
| `F8` | 記録中: 指示イベントを打つ |
| `F9` | 記録中: 休息イベントを打つ |

画面下のボタンでも同じ操作ができます。設定・使い方が開いている間は文字キーや矢印による走行操作を無効にします。記録中の F8 / F9 は設定画面内でも使えます。

## 実験データを記録する

1. 使う入力（キーボードまたはカメラ）を先に選びます。カメラの場合は片足／両足と感度も開始前に合わせます。
2. 画面下の「実験記録」を押します。
3. 氏名ではなく `P001` のような匿名の参加者IDを入力します。
4. `baseline` など、実験計画で決めた条件名を入力します。
5. 必要なら試行時間を秒で入れます。空欄または `0` は手動終了です。
6. 視点・表示・走行音を選び、「記録を開始」を押します。保存先を開けた場合だけ同じスタート地点・距離0・表示速度0へ戻り、記録が始まります。入力方式・カメラ設定・表示・音は試行中固定です。
7. 記録中は「指示」「休息」、またはメモでタイムスタンプ付きイベントを残せます（F8 / F9 でも指示・休息）。
8. 制限時間に達するか、「記録を終了して保存」で走行を停止し、保存結果を表示します。「保存フォルダを開く」からデータを確認できます。

試行時間は一時停止中も進みます。Spaceによる停止／再開は `pause` / `resume` イベントとして記録します。開始の入力不備や二重押しでは走行値を消しません。保存エラーの場合は停止して警告を出し、途中までのファイルを残します（要約JSONが完成していない可能性があります）。

保存先は Windows ではドキュメント内の `VirtualRideResearchData` です。macOS / Linux でも Documents 配下が使えればそこへ保存し、使えない場合は Unity の `persistentDataPath/VirtualRideResearchData` へフォールバックします。実際の場所は実験記録画面に表示されます。カメラ映像は保存せず、入力から得た数値・走行状態・イベントだけを記録します。列の定義と分析上の注意は [Docs/RESEARCH_LOGGING.md](Docs/RESEARCH_LOGGING.md) を参照してください。

記録中に入力方式を切り替えようとすると、切り替わらずに理由が表示されます。カメラ計測中の回転数・速度は未検証の推定値であり、画面にもその旨を表示します。

## カメラ計測の置き方

1. PCの内蔵カメラまたはUSBカメラに、ペダルと足元が横から映るようにします。
2. カメラ自体は揺れないように固定します。
3. 画面の「カメラ計測」を押します。
4. 3〜5秒ほど一定のペースで漕ぎます。
5. 「検出中」と回転数が表示されたら走行が始まります。

両足が映るか片足だけ映るかは、カメラ画面内のボタンで切り替えられます。実験記録を始める前に合わせてください。記録中は切り替えできません。カメラの回転数・速度は未検証の推定値です。カメラ映像の差分だけをメモリ上で計算し、映像ファイルは作りません。

## Windows版を作る

Unityメニューの `Tools > Virtual Ride > Build Windows` を選ぶと、`Builds/Windows/VirtualRide.exe` が作られます。`Builds` は自動生成物なのでGitの対象外です。

## 専用センサーへの拡張

走行部分は `IRideInputSource` だけを参照します。Bluetoothセンサー用クラスでこのインターフェースを実装し、`VirtualRideApp.AttachExternalInput(...)` に渡せば、コースや表示を変えずに入力だけを交換できます。詳しくは [Docs/SENSOR_INTEGRATION.md](Docs/SENSOR_INTEGRATION.md) を参照してください。

## 現時点の注意

- カメラ方式は「動きの周期」からの推定です。照明、服装、背景、カメラ位置で精度が変わります。
- 現段階は体験と実験手順を検討するためのプロトタイプで、速度計測の妥当性検証はまだ行っていません。
- 「揺れなし」は演出上の揺れと視野角変化を抑える設定で、体調への影響が検証済みという意味ではありません。不快な場合は中断してください。
- 景観の配置・天候・ルートは再現可能な固定条件です。波のアニメーション位相やPCの描画間隔まで同一とは限りません。
- 記録機能はデータ収集の土台です。研究利用前に、カメラ推定値と基準センサー値の一致度を別途検証してください。
- 専用センサーとのBluetooth接続は、センサー機種を決めた後の次段階です。
- 初版は自動操舵です。ハンドル操作、分岐、障害物、ゲーム課題は後から追加できます。

## 主な構成

```text
Assets/VirtualRide/Scripts/
  Core/    走行全体の制御、自転車視点
  Input/   キーボード、カメラ、将来センサー用の入力境界
  World/   周回経路と3D景観の自動生成
  UI/      速度や計測状態の画面表示
```

## 開発時の自動確認

Windowsビルドを `-virtualRideSmokeTest -smokeOutput <出力フォルダ>` 付きで起動すると、模擬走行・入力ロック・開始失敗・時間終了・書込み失敗・JSONの文字処理を確認し、景観5地点と設定画面のPNG、`result.json`、短時間の描画計測 `performance.json` を出力して終了します。カメラは起動しません。画像出力はこの明示的なQAモードだけの機能で、通常の実験記録では画面・カメラ画像を保存しません。
