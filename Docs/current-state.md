# Current state

最終更新: 2026-09-25

## 現在の状態

- Unity 6000.5.7f1 の Windows 向け実験プロトタイプ。Meta Quest 3 単体版（Android/OpenXR APK）を同じプロジェクトから別ビルドできる。Quest版はBK9C直結と、外部カメラをPCにつなぐ「PC中継」の2構成。
- 起動時生成の 3D 田園コース、自転車視点、自動操舵、速度・回転数・距離・時間・平均/最高速度の HUD がある。現行景観は `valley-zones-2026.09.2`（区間ごとの針葉樹・ボート・街灯と時計塔・風車と花畑・秋色並木、道端の反射ポール、木の重なり回避）。Questで地形がNaNになり消えていた不具合を修正した。
- 200 mごとの距離看板は、周回に応じてスタートからの累計距離を表示する（フォントを使わない線描画）。実験設定で表示／なしを選べ、記録中は固定、要約JSONの `distanceSignsVisible` に記録する。初期値は表示。
- キーボード、PCカメラ、Windows BLEケイデンスセンサーの入力を切り替えられる。キーボードは40 km/h、全入力の走行側は45 km/hで上限を設けている。
- カメラ計測では、Windows が認識するカメラを ◀ ▶ で選び（選択は PlayerPrefs に保存）、解析範囲を全体／下半分／左半分／右半分／中央から選べる。真っ暗な映像（2秒）と止まった映像（3秒）はエラー表示にして走行を止める。要約JSONに `camera.deviceName` と `camera.measurementRegion` を記録する。
- カメラ・BLE・キーボード表示は共通の `CadenceSpeedMapping`（`progressive-gear-2026.09`）で換算する。60 rpmまで4.2 m/回転、60〜110 rpmで6.0 m/回転まで直線的に増やし、上限45 km/h。例: 70 rpm≈19.1、90 rpm≈28.5、110 rpm≈39.6 km/h。要約JSONの `speedMapping` に記録する。一定速度の比較条件は5〜35 km/h。PC中継はPC側で換算した速度を送るため、PCとQuestは同じ版を使う。
- `IRideInputSource` により入力方式を走行ロジックから交換できる。WindowsビルドにはBLE接続ブリッジを同梱する。
- Windows BLEブリッジの出力区切り文字を保持する修正を行った。BLE一覧は既知のケイデンス機器名を優先し、4件ずつページを切り替える。Quest側は別のAndroid BLE実装で、実機検索の原因はまだ未確定。
- Quest 3でアプリのBluetooth権限は許可済み、BLEスキャナー登録も成功。連続再検索に対するOSの検索頻度制限と、画面が0件になる現象を確認した。検索中の再要求で結果を消さない修正版APKを作成し、広告受信数・候補数を状態文へ追加した。実機での再検索・BK9C接続は未確認。
- `QA/smoke` と `QA/smoke-final` に既存の画面・ログ・結果 JSON がある。
- 視点の揺れなし・固定視野角、「景色に集中」表示、実験前の視点・音設定、共通スタート位置、停止/再開マーカー、保存結果の表示を備える。CSVは20列のスキーマ2を維持する。

## 既知の注意点

- カメラ方式は照明、服装、背景、カメラ位置で精度が変わる近似推定で、妥当性検証は未完了。
- カメラ方式とBLE方式は基準機器との妥当性照合が未完了。BK9C実機での広告・GATT接続・回転数追従は未確認。
- 初版は自動操舵で、ハンドル操作、分岐、障害物、ゲーム課題は未実装。
- `Builds/`、`Library/`、`Temp/` など Unity の生成物は編集対象・Git 対象を確認して扱う。
