# BLE検索時間と再検索の改善

- Windowsは12秒、Questは10秒だった検索時間を、ともに30秒へ延長。
- WindowsのUnity入力とブリッジで検索中の再要求を無視する。開始直後のOS状態反映前にも二重開始しないよう要求フラグを使用。
- 再検索時に候補を保持する。Questは再検索時に最終受信から2分以上経過した候補を除去し、明示切断・バックグラウンド移行では従来どおりクリアする。アドレスはファイルに保存しない。
- Windowsブリッジを再生成。SCANを連続2回送る検証で開始1回・終了1回・広告130件・ERROR 0件を確認。周辺広告の受信確認であり、BK9Cの実機確認ではない。
- WindowsとQuestの最終ビルド成功。Windows同梱ブリッジのハッシュ一致を確認。
- 非表示起動の初回smokeはスクリーンショット欠落で失敗。描画可能な起動で再実行した `QA/ble-search-final/result.json` は passed=true（走行、UI、記録、終了条件等）。
- 接続されたQuest 3へ `adb install -r` がSuccess。更新日時と起動プロセスを確認。取得したアプリログに致命的例外はなかった。ヘッドセット内の見え方と検索改善の実測は未確認。
- ユーザーはBK9CのQuest接続・走行を以前確認済み。今回はセンサーが手元にないため、次回現場で検出までの時間、再検索、接続・rpm追従を確認する。
